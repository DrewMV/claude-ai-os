# Offboarding Team Members (A-INFOPS ART)

Source: A-INFOPS ADO wiki page *"Offboarding Team Members"* — child page of [[Team/onboarding-new-team-members]]. ART-level standard, applies to every INFOPS agile team including CMDB-CSDM.

## The Steps

| # | Item | Owner | Status | Date | Notes |
|---|---|---|---|---|---|
| 1 | Remove from `SAFe Master Roster.xlsx` → **Infrastructure and Operations** tab | | | | |
| 2 | Revoke INFOPS ADO project access | | | | |
| 2b | Confirm **Basic ADO license** removed if no longer needed | | | | |
| 3 | Remove from **Infrastructure and Operations ART** Teams site | | | | |
| 4 | Mark **inactive** in the SAFe Training Tracker Log | | | | |
| 5 | Notify Product Owners and relevant team leads | | | | |

Step 2b matters for cost — a Basic license left assigned keeps billing. "If no longer needed" covers the case where the person stays at PPL on another ART.

## Notes for CMDB-CSDM

- Also update [[Team/team-roster]] and [[Team/capacity]] — neither is on the ART page, but both go stale otherwise. Capacity in particular feeds iteration planning.
- **The source page is narrower than onboarding.** It does not cover several things onboarding grants. Confirm per person:
  - **IT Reinvention** Teams site (granted to POs, SMs, Product Analysts at onboarding step 11) — no removal step exists.
  - SRS-granted application access: ServiceNow ITIL role, Lucidchart, Miro.
  - Recurring ceremony invites, Demo Day series, I&A, PI Planning.
  - Reassignment of open ADO work items still owned by the person.
- For Accenture team members, offboarding from the ART is not the same as rolling off the engagement — the Accenture-side process is separate and not documented on this wiki.
